# مرصد السوق — ICT/SMC Explainable Analysis

واجهة عربية لتحليل الشموع المغلقة عبر عدة فريمات، اختيار منصة البيانات، وعرض TP1/TP2 أو Runner بوضوح، مع متابعة تلقائية للصفقة وتوثيق نيويورك/دمشق.

> **تعليمي فقط.** لا يضع أوامر في أي منصة ولا يضمن نتائج. لا تدخل مفاتيح تداول Exchange في المشروع.

## أهم التغييرات

- تختار **منصة البيانات**: OKX / Binance / KuCoin / Gate.io / Bybit / MEXC أو Auto.
- تختار فقط فريم التنفيذ `5m/3m/1m`؛ التحليل يجلب `1D → 4H → 15m` تلقائياً.
- كل الفريمات من نفس المنصة، وكل الحسابات على **شموع مغلقة**.
- كل تحليل يحمل `audit_id` ووقت نيويورك ودمشق.
- `PENDING_SETUP` للمراقبة، وليس Limit Order.
- TP1 مستوى سيولة حقيقي؛ TP2 يظهر فقط بدليل كافٍ، وإلا Runner/Trailing.
- متابعة بضغطة: Entry → TP1 (50% + BE) → TP2 أو HL/LH trailing.
- لا حد يومي/شهري مصطنع لعدد الصفقات.

اقرأ نتيجة البحث والتدقيق كاملة في [`ICT_AUDIT_AR.md`](ICT_AUDIT_AR.md).

## لماذا فريم واحد في النموذج؟

الحقل اسمه **فريم التنفيذ**:

| الفريم | دوره |
|---|---|
| 1D | الانحياز وDraw on Liquidity الكبير |
| 4H | السياق ومناطق HTF |
| 15m | السيولة/الهيكل/FVG داخل الجلسة |
| 5m / 3m / 1m | تأكيد وتنفيذ؛ هذا فقط ما تختاره |

`5m` هو الافتراضي لأنه أوضح وأقل ضجيجاً من الدقيقة للمبتدئ.

## اختيار المنصة وسلوك الخطأ

الاختيار الصريح مثل `okx` لا ينتقل إلى Binance بصمت. تظهر محاولة الجلب والرسالة الفعلية. `auto` وحده يسمح بالتجربة بالترتيب، وبعد نجاح منصة يثبتها لكل فريمات التحليل.

الفريم غير الصحيح مثل `7m` يُرفض؛ لا يتحول بصمت إلى `15m`.

## الاختبارات

```bash
pytest -q
```

تغطي الاختبارات:

- صيغ السعر، ومنها `1.769.75` والأرقام العربية.
- strict timeframe/exchange behavior.
- حذف الشمعة المفتوحة وترتيب/إزالة تكرار الشموع.
- TP هيكلي مرن بلا فرض 3R.
- دورة TP1 → Break-even → TP2.
